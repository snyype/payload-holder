Your JSON payloads, one command away.

Save request bodies, test fixtures and API snippets under a name, then pull them back from cmd, PowerShell, Git Bash, macOS or Linux — the same payload everywhere.

$ curl -fsSL https://raw.githubusercontent.com/snyype/payload-holder/main/install.sh | sh

Run in Git Bash (Windows), macOS or Linux. Re-run any time to update — it skips if you're already on the latest release. Every download is checked against the release's SHA256SUMS; on a mismatch it warns and installs nothing.

Why payload

Small on purpose. Your payloads are plain files you can read, diff and back up.

1×

One binary, every shell

Compiled Go with no runtime. The same exe behaves identically in cmd, PowerShell and Git Bash.

{}

One file per key

Each key is <key>.json in C:\payload (or ~/payload). Point PAYLOAD_STORE elsewhere if you like.

↻

Self-updating installer

The install script checks payload version and only downloads when a newer release exists.

⌨

Edit with arrow keys

Arrow-key menus to pick keys, and a JSON editor with live validation for store and update. payload copy puts a payload on your clipboard.

✓

Open source

MIT licensed, built by GitHub Actions from tagged source. Windows may warn because it is unsigned — here's why.

⌂

Stays local

No accounts. Payloads never leave your machine — the only network call is a daily check for new releases, which you can turn off.

Commands

Everything it does, on one screen.

payloadPick a saved key from an arrow-key menu and print its JSON
payload <key>Print that key's JSON directly — no menu, so you can pipe it
payload storeEnter a key name, then type or paste JSON in the editor (asks before overwriting)
payload updatePick an existing key and edit its current JSON in place
payload copy [key]Copy that key's JSON to the clipboard, or pick one from a menu when no key is given
payload drop [key...]Delete the named keys, or pick several from a menu (1 3 5-7 or all) — always asks to confirm
payload listPrint key names only — handy for scripts (also payload | grep test)
payload table [page]Browse keys in a table, 10 per page — ←/→ to page, ↑/↓ to select, enter to view, c to copy, d to delete
payload pathPrint the storage folder
payload settingsPrint the path of the key-bindings settings file
payload setupCreate the settings file if it's missing and refresh the AI README (the installer runs this)
payload versionPrint the installed version
payload doctorCheck the install and, when a newer release exists, update in place

In the JSON editor, arrow keys, Home/End and PgUp/PgDn move the cursor, Ctrl+S saves and Esc cancels. When input is piped (or in Git Bash), paste instead and finish with Ctrl+Z then Enter on Windows, or Ctrl+D on macOS/Linux.

Install options

The one-liner covers most people. Here's the rest.

curl -fsSL https://raw.githubusercontent.com/snyype/payload-holder/main/install.sh | sh
# Windows → C:\payload\bin (added to your user PATH)
# macOS / Linux → ~/payload/bin (added to your shell profile)

Open a new terminal afterwards so the PATH change applies. The installer lays out the payload folder like this, and moves an older install (in C:\payload or ~/.local/bin) into bin:

C:\payload\                  # ~/payload on macOS / Linux
├── <key>.json               # your saved payloads
├── README.md                # guide for AI assistants
├── bin\payload.exe          # the binary, on PATH
└── customization\
    └── settings.json        # key-binding overrides
# install a specific release (also allows downgrading)
curl -fsSL https://raw.githubusercontent.com/snyype/payload-holder/main/install.sh | PAYLOAD_VERSION=v1.1.0 sh

# reinstall the same version / choose the install folder
curl -fsSL https://raw.githubusercontent.com/snyype/payload-holder/main/install.sh | FORCE=1 INSTALL_DIR="$HOME/bin" sh
git clone https://github.com/snyype/payload-holder.git
cd payload-holder
go build -o payload.exe .   # or: go build -o payload .

Needs Go 1.26+. On Windows with Smart App Control on, unsigned builds are blocked — see If Windows blocks payload.

Customization

Rebind any key in the table and the JSON editor. Your settings override the defaults — delete the file to go back.

Edit customization/settings.json in the payload folder (payload settings prints the path). Each action takes a list of keys; any action you leave out, or the whole file if you delete it, falls back to the built-in keys. Ctrl+C always quits, and the help lines show whatever keys you choose.

{
  "update_check": true,
  "keybinds": {
    "table": {
      "up": ["up", "k"],          "down": ["down", "j"],
      "next_page": ["right", "l", "pgdown", "n", "space"],
      "prev_page": ["left", "h", "pgup", "p"],
      "first": ["home", "g"],     "last": ["end", "G"],
      "view": ["enter"],          "copy": ["c"],
      "delete": ["d", "delete"],  "confirm_delete": ["y", "Y"],
      "quit": ["q", "esc"]
    },
    "editor": { "save": ["ctrl+s"], "cancel": ["esc"] }
  }
}

Key names: letters as typed (case matters), space, enter, esc, tab, delete, arrows (up, left, …), home/end, pgup/pgdown, and modifiers like ctrl+s or alt+x. The installer creates the file once and never overwrites it; run payload setup to recreate it.

The installer also writes a README.md into the payload folder that explains to AI assistants what payload can do, where payloads live and how to use it without the interactive menus. Point Claude, Copilot or any agent at it.

Downloaded manually? Rename it to payload (payload.exe on Windows), put it in a folder on your PATH, and on macOS/Linux run chmod +x payload.

To verify a manual download, get SHA256SUMS from the same release, put it next to the file and run sha256sum -c SHA256SUMS --ignore-missing (macOS: shasum -a 256 -c SHA256SUMS --ignore-missing). It should print OK.

If Windows blocks payload

payload's Windows binaries are not code-signed. Windows doesn't let unsigned apps run while some of its protections are on, so you may see one of these. It happens because the binary is unsigned, not because Windows found anything harmful in it.

  • "Windows protected your PC" (SmartScreen), usually after downloading the .exe in a browser: click More info → Run anyway.
  • Permission denied / "An Application Control policy has blocked this file" (Smart App Control): Smart App Control has no per-app allow list, so the only way to run payload is to turn it off in Windows Security → App & browser control → Smart App Control settings → Off. On some Windows 11 versions it can't be switched back on afterwards without resetting Windows.

It is safe to allow payload: it is open source (MIT), every release binary is built by GitHub Actions from this repository's tagged source, and its only network use is a once-a-day check for new releases on GitHub (which you can turn off) and the download when you choose to update. Prefer to check for yourself? Build it from source (see Install options).

Privacy policy: this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. The daily update check sends only a request for the latest release tag to GitHub and can be turned off.
